# 界面文字规范

界面、通知、错误提示、对话里系统生成的提示行、使用文档，一律用规范的书面中文：简洁、准确，不用口语词。助手的回复也按这个要求写（提示词里写明）。

## 原则

- 用书面词，不用口语词：「执行任务」不说「干活」，「确认」不说「拍板」，「受阻」不说「卡住」。
- 一句话说清用途，不解释实现。设置项的说明写「这一项决定什么」。
- 错误提示写清发生了什么、怎么处理：「保存失败：时区无效。」「无法连接到 Hob，请检查网络或确认服务已启动。」
- 动作用统一的动词：创建、保存、删除、运行、停止、查看、生成、分派、确认、取消。
- 不出现底座的名字（pi）。
- 不用破折号，不用感叹号，不加语气词。
- 助手档案的「补充说明」记录该助手需要知道的事实，不称为做法；做事方式放在规则或技能中。

## 术语

| 不要写 | 写成 |
|---|---|
| 干活（模型角色） | 任务执行 |
| 默认干活模型 | 默认任务模型 |
| 派活、派任务 | 分派任务 |
| 能派的模型 | 可分派的模型 |
| 定位（模型的一句话说明） | 用途说明 |
| 同时干活数 | 最大并行任务数 |
| 多久没动静算卡住 | 无响应判定时间 |
| 正在做 | 进行中的任务 |
| 现在没在干活 | 当前没有进行中的任务 |
| 看过程 | 查看详情 |
| 工作记录（全部任务） | 任务记录 |
| 等你批 | 待确认 |
| 完成 | 已完成 |
| 卡住 | 受阻 |
| 规矩 | 规则 |
| 所有助手共用的规则 | 全局规则 |
| 全局 allow 规则 | 一律照做 |
| 要先问你 / 先问 | 执行前确认 / 需确认 |
| 直接做 | 直接执行 |
| 刚改 | 最近修改 |
| 需要我拍板时通知我 | 需要确认时通知我 |
| 一句话职责 | 职责简介 |
| 关于你 | 个人信息 |
| 分出助手 / 分出去 | 创建专属助手 |
| 带走 N 段对话 | 迁移 N 段对话 |
| 定时 | 定时任务 |
| 要做什么 | 任务内容 |
| 什么时候 | 执行时间 |
| 试跑一次 | 立即运行 |
| 试一张 | 生成测试图片 |
| 发一条测试 | 发送测试通知 |
| 没建成 / 删不掉 / 没起来 | 创建失败 / 删除失败 / 启动失败 |
| 连不上 | 无法连接 |
| 有新版本 · 刷新 | 有新版本，点击更新 |
| Skill / skills（功能名称） | 技能 |
| 搜索能力（设置分区） | 联网搜索 |
| 搜索供应商 / 搜索引擎服务 | 服务商 |
| 生图（设置分区、助手能力） | 图像生成 |
| 生图（一次动作） | 生成图片 |
| 改文件 | 修改文件 |
| 工作（设置分区） | 任务 |
| 跑 / 读 / 写 / 改 / 搜 / 找 / 看（任务过程里的动作） | 运行 / 读取 / 写入 / 修改 / 搜索 / 查找 / 列出 |
| 群里要办的一件事 | 事项 |
| 拆出来的每一份工作（执行时就是一个任务） | 子任务 |
| 要先完成的 | 前置任务；状态「等待前置任务」 |
| 需要用户亲自做的 | 待你执行 |
| 五个阶段 | 需求澄清 → 需求说明 → 任务拆分 → 执行 → 验收 |
| 验收清单 | 验收标准 |
| 用户最初那句话 | 原始需求 |
| 把一件事立成事项（动作） | 立事项 |
| 子任务状态：还没开始执行、轮到了还没派任务、任务在跑、任务做完、任务受阻、轮到你做 | 未开始 / 待开始 / 进行中 / 已完成 / 受阻 / 待你执行 |
| 事项结束时的两种结果 | 已完成 / 已放弃（写明原因） |

表里没有的词，按同样的标准选：正式软件产品的设置页、提示里会怎么写，就怎么写。
